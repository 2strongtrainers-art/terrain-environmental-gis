# GIS root release

The source on `main` contains the GIS market preview. GitHub Pages serves the
`gh-pages` release branch. Atlas is generated by `scripts/build_atlas.py`; do not
publish the source loader at `atlas/index.html` over the generated release.
The fishing game has its own release subtree. A GIS release preserves both.

## Review and verify

1. Run **Terrain GIS Release Readiness** on the proposed source (automatic on a
   matching pull request, or manual with `target: candidate`). It has read-only
   repository permissions and cannot publish.
2. Require all steps to pass. Download `terrain-gis-readiness` for the migration,
   cache-isolation and preservation evidence, GIS synthetic browser checks, and
   Atlas navigation checks. `terrain-gis-verified-candidate` contains the combined
   Pages candidate.
3. Review the source diff and merge it into `main`. Rebuild against the latest
   `gh-pages` if the published branch has moved; do not overwrite unrelated work.

The browser check uses a disposable profile and synthetic public-service
responses. It proves import, migration, screening presentation, autosave, export,
report, sharing and mobile controls. It is not evidence of current government
service availability or a real project's environmental status.

## Prepare the Pages update

In isolated source and published checkouts:

```sh
python scripts/build_terrain_release.py --published /path/to/gh-pages --out /path/to/new-candidate --report /path/to/preservation.json
```

The builder refuses an existing output directory, never writes the input
checkout, and verifies every non-GIS file is byte-for-byte unchanged. Only these
root assets may differ:

```text
index.html
app.js
styles.css
demo.html
demo.css
demo.js
viewer.html
viewer.js
manifest.webmanifest
sw.js
share-fix.js
report-plus.js
```

Publish those reviewed files as a normal commit to `gh-pages`. Do not replace
the release branch with the source tree or dispatch the old Atlas fallback.
Run the repository's Pages deployment for `gh-pages` if a deployment is not
already triggered; wait for its successful environment deployment.

Then dispatch **Terrain GIS Release Readiness** from the merged `main` with
`target: published`. It compares the live bytes for all 12 GIS assets and the
key Atlas/game assets before running the GIS and Atlas browser flows on Pages.
The existing **Alan Fishing Escape Live QA** is available for a full game check.

## Data and cache behavior

The GIS migrates `terrainEnvironmentalGIS.v2` only if the current market-preview
save is absent. The old value remains a backup. An intentionally cleared current
project stays empty. Restore-time map/import events cannot overwrite a screening
snapshot before it is fully loaded.

The GIS service worker handles only the root application's named shell files
and retires only `terrain-gis-shell-` caches. It does not handle Atlas/game URLs
or clear their caches. This remains a same-origin shell cache; basemaps and
government data are not guaranteed offline. The pre-existing fishing worker is
preserved without changes by this release.

## Rollback

Revert only the GIS release commit on `gh-pages` and redeploy that branch. The
retained older local-storage key allows the earlier application to read its own
saved project. Work newly created in the market-preview version is in its newer
key; export needed projects before intentionally returning to the older app.
